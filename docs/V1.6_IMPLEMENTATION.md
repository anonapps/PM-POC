# ARGOS PM v1.6 implementation and acceptance

Approved sources: original v1.6 Planning requirements supplied by the owner on 26 October 2026 (REQ-001 and REQ-002), plus the consolidated implementation instructions. Development branch: feature/v1.6-consolidated-enhancements. Target v1.6.0.

1. Audit current main and existing work; reconcile original UI scope. Fit the viewport using responsive controls and wrapping record fields, never hiding columns or requiring horizontal scrolling. Verify sticky navigation, quick editing, dropdowns, filters and sorting.
2. Add optional, validated baseline storage and pure versioned historical schedule snapshots. Capture active tasks (including existing parent dates), milestones and historical stream references with stable IDs. Preserve optional legacy fields and schema compatibility; baseline-containing saves require a v1.6 reader.
3. Add named baseline CRUD, selection and shared comparison projections. Positive day variance means later; null means unavailable/undated. Added/removed is based on active entity IDs, not array order or names. Metadata renames must never alter snapshots. Collection edits participate in Undo/Redo and are independent of audit recording.
4. Reuse canonical dependencies. Add cross-stream inspection, filters, sorting, editing and informational warnings for all existing dependency types. No automatic scheduling. Invalid new references, duplicate relationships, self links and cycles are rejected without mutating state.
5. Integrate optional historical overlays/variance into Gantt, optional historical stations/dependencies into Tube Map and a comparison table. Use shared calculations; preserve live milestone positions and labels.
6. Produce a detailed populated Simple/Extended Mode mockup with toggle before Expand All, compact split layout, independent vertical scrolling, keyboard-accessible resizing, and baseline/dependency controls. STOP for explicit approval before implementing Extended Mode.
7. Extend fixtures/unit/integration/browser coverage. Run lint, typecheck, unit/integration tests, browser acceptance/regression/lifecycle/layout and build; distinguish environmental failures from code regressions. Extended Mode tests remain pending approval/implementation.
8. Update user/feature/compatibility/test docs, changelog and version references; prepare a draft PR with screenshots, test results and limitations. No release, merge or deployment without approval.

The prior reconciliation document records initial environment failures, not current validation or final release evidence. No unrelated features are authorized.
