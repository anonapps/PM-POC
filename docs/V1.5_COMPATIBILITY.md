# v1.5 `.pmp` compatibility and native acceptance

## Format and migration contract

v1.5.0-rc.1 retains PMP format 1 and project schema 2 used by v1.4. No `.mpp` format or conversion is introduced. Existing IDs, relationships, dependencies, deleted entities, identifier sequences, configuration, audit history and untouched text must survive a supported open/save cycle. The runtime version becomes 1.5.0-rc.1 on a candidate save; the existing minimum-runtime setting is retained.

Optional saved timezone metadata is added only by a successful save. It contains the saving device's timezone and UTC offset. A v1.4 file without it shows Timezone unavailable; viewing an old file must not silently write it or reformat lowercase legacy data. The technical format/schema compatibility and migration boundaries remain in PROJECT_REQUIREMENTS, PMP_FORMAT and ARCHITECTURE. An older technical schema requiring migration is not the same case as a supported v1.4 file; do not overwrite the original during migration testing. Unsupported/corrupt/future files must fail safely.

Mocked picker/writer tests validate application behaviour, not OS consent or real disk permissions. They do not mark any row below passed.

## Native Windows/macOS checklist — NOT RUN

Work on **copies** of representative real v1.4 projects plus the fictional frozen fixture. Record candidate SHA/app version, OS/Chrome version, timezone/offset, original copy SHA-256, resulting file hashes, counts and evidence. Keep a separate untouched original and never use a private project in a demo.

1. Open a copied v1.4 `.pmp` through Chrome's real picker. Confirm no write or automatic migration occurs on open and the untouched copy's hash remains unchanged. Verify legacy timezone is unavailable and lowercase notes are not reformatted merely by loading.
2. Compare Project metadata, all six entity collections, owners, multi-stream Milestones, task hierarchy, dependencies, Risk actions, Decision context, deleted entities, ID sequences, preferences and audit history with the baseline. Restore a deleted record only in a disposable copy; test Undo/Redo.
3. Edit one human-readable field and blur. Verify only its first letter changes, one Undo restores the original, Redo restores the complete edit, and audit recording adds one field event. Repeated unchanged blur adds none. Check notes whitespace/accents and technical values.
4. Save to the copy using the native permission prompt. Confirm Saved only after write success. Close/reopen in the same candidate and compare complete data. Check new saving-device timezone/offset and original local timestamp, including viewing on a device in another timezone where available.
5. Save As to another file. Verify the earlier copy is unchanged and the new active file contains all data/configuration/audit information. Cancel the picker and verify the current project remains usable.
6. Deny or revoke write permission in a disposable location. Confirm Save failure retains current in-memory work/history, last-successful timestamp and saved bytes. Restore access, Retry/Save Now and verify recovery; test Save As recovery to a writable location.
7. With dirty data, exercise Open/Close Cancel, Save and Discard. Cancel keeps current work. Save must succeed before leaving. Discard must not write; reopening the same file loads its saved state. Cancel a subsequent picker and verify active work remains available.
8. Modify a copied file externally. Verify the conflict warning and explicit Keep Current/Reload choices. Reload with dirty data requires discard confirmation; do not silently overwrite external changes.
9. Use invalid/corrupt and unsupported-version disposable files. Verify errors without damaging the active project or original files. Confirm a technical migration prompt follows the existing policy when applicable.
10. Reopen the successfully saved copy in the supported v1.4 baseline only as a separately backed-up interoperability check. Optional timezone metadata must not be mistaken for a new project schema. Record actual results; forward readability is not asserted from a v1.5-only test.

**Record results separately for Windows Chrome and macOS Chrome. All native rows remain unexecuted until evidence is supplied.** No release freeze or publication is authorised by these instructions.
