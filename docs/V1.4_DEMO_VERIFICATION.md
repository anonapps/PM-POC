## Editorial rationale

Current [LinkedIn video guidance](https://business.linkedin.com/advertise/ads/sponsored-content/video-ads/tips) supports visual storytelling, sound-off comprehension and longer product stories when the objective warrants them. [Google Ads' ABCD guidance](https://support.google.com/google-ads/answer/14783551?hl=en) supports early/continuous branding, focused messages, contrast and a clear next step. This demo applies those principles with short chapter headlines, a separate high-contrast editorial header, normal-speed action/result sequences, reading pauses and a closing GitHub invitation. The cream/coral styling and framed layout are editorial design choices, not changes to the application UI.

## Capture boundary

The managed browser's filesystem guard policy disables native file pickers. Capture uses the repository's isolated in-memory picker boundary from `e2e/acceptance.mjs`, starting with a new empty fictional project. The real application performs creation, serialization, autosave and Save Now through its normal Project File Service. Serialized bytes were exported to a disposable `.pmp` and inspected. No existing user project was opened or overwritten, and no cloud data service was used.

This verifies the application save flow and resulting contents, **not native OS picker consent or direct browser disk writes**. The video shows no OS dialog. Native picker acceptance remains a manual check in a browser that permits filesystem access.
