## Mathematical contract

Use UTC integer calendar-day ordinals after existing strict date validation; do not read the clock. A scheduled task's inclusive duration is `finish - start + 1`, with endpoint offset `h = duration - 1`. A linked milestone has duration and offset zero. Unlinked milestones and parent/membership associations do not add scheduling constraints. All nondeleted tasks participate, including independent and completed tasks; actual completion dates do not replace planned duration.

For each existing relationship from i to j, express `ES_j >= ES_i + w`:

| Type | w |
|---|---|
| FS | h_i |
| SS | 0 |
| FF | h_i - h_j |
| SF | -h_j |

The absent stored lag/lead is zero. Planned starts and finishes establish durations and comparison warnings, not hard constraints. Project End and stream planned boundaries are not deadlines.

Forward pass: `ES_i = max(Project Start, ES_predecessor + w)`; `EF_i = ES_i + h_i`. Completion T is the latest calculated finish of all eligible tasks and linked milestones, including independent nodes and non-sinks. Backward pass: `LS_i = min(T-h_i, LS_successor-w)`; `LF_i = LS_i+h_i`. Total float is `LS_i-ES_i`; free float is the minimum of completion slack and each immediate edge slack `ES_j-ES_i-w`. Zero float means critical only when reliable; negative float is never automatically critical. With no extra deadlines, a complete consistent graph cannot produce negative float.

Per-stream calculations retain the full project forward graph. T_stream is the latest calculated finish among scope members. Run the full backward graph with T_stream bounds on scope members and global T bounds on other nodes, respecting every cross-stream relationship. Display filters never change mathematics or chart criticality. Multi-stream milestones participate in each assigned stream.

Count maximal sequences in the tight zero-float graph using a topological bigint dynamic program, not path enumeration. Duplicate dependency records for the same entity pair cannot multiply paths; retain the strongest constraint for the pair. Independent critical nodes are single-node sequences. Scoped counts include maximal critical sequences that touch the scope.

## Partial reliability and failures

Missing/invalid dates and invalid active references block affected dates and propagate downstream. Iterative strongly connected component analysis isolates cycle members and their dependents; unaffected earliest dates remain available. A globally unknown horizon conservatively prevents reliable float and criticality, even on otherwise dated components. Dates, float and criticality have independent reliability flags. Reliable completion from remaining activities is labelled provisional if unresolved input could change it. Missing metrics remain blank/dashes, never invented zero values.

Schedule conflicts with planned values produce Partial warnings while dependency-consistent calculated results can remain reliable. Links to deleted successors are excluded but reported; unresolved predecessors can block active successors. Native import still rejects corrupt missing/cyclic relationships; the engine's defensive handling protects runtime calculations without silently repairing imports.

Worker failures publish Unavailable while leaving the project usable. Refresh starts a new revision; prior results are explicitly outdated and excluded from highlighting/export. In-memory scoped results are cached only for the current mathematical revision. Renames, saves and baseline changes do not invalidate mathematics; UI and CSV use current task names. Project close disposes the worker, timers and subscriptions.
