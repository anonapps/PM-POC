# Read this first

This manual describes **ARGOS PM Version 1.7.0**, an unpublished release candidate. It is bundled locally under **File Information → UI Reference Manual**. No GitHub release or deployment is implied. This is a text reference to implemented controls; no new screenshots or demo footage are claimed.

ARGOS PM is a local-first project workspace for desktop Chrome on macOS and Windows. The self-contained `.pmp` file is the source of truth. No account, external database or online calculation service is needed. Keep a separate untouched copy of valuable files before cross-version testing.

## Start, open and create

Run the local application and use **New Project** or **Open Project**. A new project requires Name, Start date and an explicitly selected Status. Description and End date are optional. Complete required fields, choose File & Create, select a local filename and grant browser write permission. Cancelling a picker does not create a project. Corrupt and incompatible project files are rejected with a clear error; required technical migrations preserve the original file.

## Save, switch and close

The header shows saved/unsaved state, **Save Now**, **Undo** and **Redo**. Autosave checks dirty state every 60 seconds. File Information provides **Open Project**, **Close Project** and **Save As**. Dirty close/switch presents Save, Discard and Cancel; a failed save keeps work in memory. Retry after restoring access or use Save As. When a file changed externally, review Keep Current or Reload from File before overwriting anything. Saved timestamps retain the original saving device's timezone information when available. Chrome controls file consent and does not disclose the full folder path.

## Records, search and history

Use the sidebar to open Streams, People, Tasks, Milestones, Risk Log and Decision Log. **Add** opens the shared right-side form. Fields marked with an asterisk are required. Use Create to commit, Cancel to discard, and the normal inline/context editors to update existing records. Task hierarchy, people/owners, scopes and relationships remain part of the canonical project. Deleted records are distinct from active records; use the appropriate page's Show Deleted controls when available.

Search is live and combines with selected filters. Categories combine with AND; multiple values in a category combine with OR. Clear all resets search and filters. Click column headings to sort. Search/filter and chart-selection states do not change project data. Warnings are informational; review the record or relationship before making an explicit correction. Risk Matrix and context controls retain their normal behavior.

Undo and Redo operate on committed edits. Optional Audit Log recording is controlled in File Information, retains a bounded recent history and offers CSV. Recording does not replace the project file or provide a backup. Native keyboard focus and control behavior follow the browser; labelled controls support keyboard use.

# Planning workspace and baselines

## Fit the workspace

Desktop record pages retain continuous table headings and aligned fields. On genuinely narrow workspaces, supported record fields wrap into labelled groups; Extended Tasks keeps its continuous row layout with every column visible. No fields or actions are removed: use vertical scrolling to reach the last record. The sidebar keeps all navigation entries visible without its own scrollbar and can still collapse. Gantt and Tube Map move through time with Previous, Next and Jump to today, rather than horizontal scrolling.

## Baselines

Open **Baselines** in the sidebar. Open the ellipsis actions menu beside the selected baseline in the title/Search toolbar and choose **Create baseline**, enter a required name (up to 200 characters) and optional description (up to 20,000 characters), then Create. A baseline records active task and milestone dates, names, stable IDs and historical stream references at that moment. It does not copy risks, people, decisions, attachments or executable content. Renaming a task, editing dates or deleting a live entity never changes a saved historical schedule.

Create multiple named baselines to keep different commitments. The toolbar comparison selector chooses the baseline used across views. **Manage baselines** opens the complete dated/described list; **Rename** and **Delete** are available through the actions menu. Selection is session-only and defaults to the first baseline after reopening. Rename changes name/description only; Delete requires confirmation. Undo/Redo applies to creation, rename and deletion. Baselines remain available when audit recording is disabled.

The comparison table shows baseline and current start/finish dates, day variances, stream names, entity IDs/names and Matched/Added/Removed status. Positive variance means later, negative means earlier; zero means the same date. An unavailable date shows Undated and its variance shows —. Search, filters and sorting change the display immediately without editing data. Click any of the nine column titles to alternate ascending/descending order; keyboard activation is also supported. Dates sort chronologically and variances numerically, with missing values last. Removed means absent from the active current schedule, including soft deletion. Historical stream names remain available even when a live stream has been removed.

## Gantt baseline controls

Select a comparison baseline below the Gantt toolbar. **Baseline overlay** adds muted dashed historical bars or milestone markers alongside the live schedule. **Variance indicators** shows start/finish day differences for live rows. **Dependencies** toggles existing supported chart connectors. Week, Month and Quarter use the same historical calculations. Added/removed entities and offscreen historical dates remain available in the comparison table; the chart does not invent live rows for deleted entities. Quick edits, stream links, filters, collapse/expand, zoom and persistent date navigation continue to operate on the live project.

## Tube Map baseline controls

**Baseline milestones** adds a separate historical strip aligned to the visible date window below the live map. Hollow indicators show baseline milestone dates and preserve historical stream assignments. Hover or focus an indicator to read its milestone ID/name, historical date and current date. Coincident historical indicators share a date; the comparison table exposes all records individually. The separate strip preserves live station geometry, captions and quick-edit targets. **Dependencies** shows/hides milestone connections without deleting relationships.

## Dependencies

Open **Dependencies** for a project-wide relationship list. Search by item, stream, relationship type or warning; filter to cross-stream links, warnings and supported types. Sort by predecessor, successor, type, streams or warning count. Cross-stream means both endpoints have assigned scopes with no shared stream; Project-wide is an explicit scope, and unassigned items cannot establish a cross-stream classification.

Choose **Inspect / Edit** to change predecessor, successor or type on the existing relationship. Dynamic endpoint selectors are searchable and show stable human-readable IDs. Self-links, cycles, duplicate endpoint/type combinations and invalid/deleted new endpoints prevent saving. The relationship retains its original stable ID. Create new links using the existing Tasks/Milestones controls.

Finish-to-Start, Start-to-Start, Finish-to-Finish and Start-to-Finish values are retained and inspected. Schedule conflict warnings compare the corresponding start/finish dates; missing dates/references and deleted endpoints are reported. Warnings are informational, recalculate after edits and never move dates. Existing chart-specific connection support remains unchanged.

## Project files and history

All baseline data lives inside the same `.pmp` file, behind the existing Project File Service. Existing v1.4/v1.5 files open without a new technical schema migration and preserve their data on save/reopen. A file containing baselines declares a minimum v1.6 runtime to protect historical data from older readers. Preserve the original file if you need to continue using an older application. No automatic downgrade or cloud storage is introduced.

Snapshot schema version is 1; the existing project schema remains 2 and PMP container format remains 1. The parser validates historical IDs, dates, scope references and collection bounds. Baseline collections have a 1,000-entry safety bound and existing archive/entry limits still apply. Comparison uses calendar days independent of daylight saving time. Audit recording remains optional and independent of baselines; baseline collection/metadata changes are recorded when audit is enabled.

## Gantt Extended Mode

Choose **Extended** immediately before Expand All to display the compact Gantt above the Tasks workspace. Choose **Simple** to return to the full-height chart. The standalone Tasks page and Simple Gantt keep their standard spacing. Task fields, actions, filters, sorting, creation, deletion/restoration and dependencies use the same existing module and canonical project data.

The two Search fields stay centered on the full page content at the same horizontal position as other pages. Each pane has independent vertical scrolling. Gantt date headings and navigation remain accessible; Tasks keeps its own sticky toolbar/headings. Status colors are unchanged. Baseline overlay, comparison selection, variance and dependency visibility work in both modes.

Drag the horizontal separator to resize the panes. Keyboard users can focus the separator and press Up/Down to move it by 16px, or Shift+Up/Down by 64px. Both panes retain usable minimum heights; shorter windows allow outer vertical scrolling. The split and selected mode are session-only and return to Simple after closing/reopening the project.

**Add Task is exactly the existing standalone Tasks creation panel**: same size, page-level right-edge position, field distribution, whitespace, fonts, required/optional fields, validation and keyboard behavior. The full-height panel overlays both panes and the project header. Only its form body scrolls; its header and Create/Cancel footer remain available. The compact pane styles do not apply to the panel. Escape/outside dismissal of a populated draft asks Stay/Discard; Cancel discards immediately, as on standalone Tasks.

Both panes update together. Task quick edits, creation and deletion participate in the existing Undo/Redo and optional audit history. Live edits never modify immutable baselines. Switching mode preserves each pane's search/filter state. No automatic scheduling is introduced.

The complete v1.5 user reference remains bundled at `/manuals/1.5/ARGOS_PM_UI_REFERENCE.pdf` for established module operations. The version-matched v1.6 guide is bundled at `/manuals/1.6/ARGOS_PM_UI_REFERENCE.pdf`. Earlier v1.5 demonstration footage remains historical; it is not a v1.6 recording.


## Safe save limits and historical stream names

Saving checks the same 16 MiB per-entry and 32 MiB total archive limits used when opening files, including UTF-8 byte sizes and container overhead. If accumulated history exceeds these limits, saving fails before a file writer is opened. The prior successfully saved file remains unchanged and reopenable; current edits remain in memory. Remove unneeded baselines using the normal confirmed deletion flow, or reduce project content, before retrying. History is never pruned automatically.

The comparison table uses historical stream names for baseline associations and current names for live associations. If a stream is renamed or an entity moves, both values are shown when they differ. Removed items retain their historical names. Search matches the appropriate historical/current names, and stream filters display both names for renamed IDs.

Record tables reserve the ID/name space above the field band and keep a small lower inset. Headings use a shorter band; scope fields can grow when several pills wrap, with the remaining fields aligned. Notes remain editable and vertically resizable.

In Warnings, click the warning title, entity information or description to open the related module and targeted record. Keyboard users can focus that same content and press Enter or Space. The separate Open button is removed; explicit corrective actions still require their established confirmation.

Dependencies uses the shared compact typography and row rhythm. Hover over abbreviated entity, scope or warning text to inspect the full value; Inspect / Edit retains the complete relationship and warning information. Search/filter/sort still matches full values. Gantt Search now uses the standard 340px size and the same centered position/fallback as ordinary pages. At narrow widths, the standard Search row appears below the title/actions instead of shrinking the search field.

Milestone dependency warning indicators sit beside the predecessor field on the same control band. Click or focus the indicator to open the existing measured warning popup; Escape dismisses it without changing dates or relationships.

# Critical Path Analysis

## Enter Extended Mode

Open **Gantt**, then select **Extended** immediately before Expand All. The chart remains above a resizable divider. The lower pane offers compact **Tasks** and **Critical Path Analysis** tabs. Entering Extended Mode normally opens Tasks; the Overview Critical Path shortcut deliberately opens Analysis. Returning from Simple Mode opens Tasks again.

Use Left/Right arrows or Home/End on the tabs; the active tab has a distinct border and visible focus. Use the divider with pointer dragging or its Up/Down arrows (Shift for larger steps). The panes scroll independently. The full Task creation drawer remains the same as standalone Tasks.

## Scope, results and reliability

Project-wide is the default calculation scope. Select a stream in the Scope control for stream-relative results; cross-stream dependencies remain part of the calculation. Display search and stream/critical-status filters do not recalculate the mathematical scope. The calculation uses Project Start, inclusive calendar-day task durations, all four supported dependency types and zero-duration linked milestones. Calculated dates respect dependencies and are separate from planned dates. Same-day Finish-to-Start is supported. Planned dates, baselines and canonical relationships are never automatically changed.

The summary shows critical-task count, distinct critical-path count and calculated completion. The table shows calculated start/finish, Critical/Noncritical/Unresolved/Unscheduled and total/free float. Sort headings normally. Expand a row for planned versus calculated dates, latest dates, reliability, relationships and warnings. Expand All/Collapse All affects details in the calculation scope.

**Up to date** means calculations completed. **Partial** means input or planned-schedule issues need review; reliable portions can still be shown. A provisional completion is labelled explicitly. Unreliable float and criticality remain blank rather than invented. Cycles and affected downstream activities are unresolved; unrelated reliable dates can remain available. Missing, invalid or reversed planned dates are **Unscheduled** and remain discoverable with that filter. Add or correct dates through Quick Edit; classification alone never repairs a schedule.

Linked milestone scheduling warnings appear in the related task's expanded details, labelled with the milestone identity. Their descriptions and warning identities are shared with the Warnings page; opening details does not create additional warning records. Review the relationship in Dependencies and edit the intended record explicitly.

## Select, reveal and correct

Select a task's name in Analysis to reveal its Gantt row, navigate to its date window if scheduled and temporarily highlight it. The chart scrolls only when needed; the analysis pane and page remain stationary. Search/status filters and sort preferences stay set. A hidden task is temporarily revealed, including within a collapsed stream. The stream's disclosure reports its actual expanded display; Escape clears the reveal and restores the user's collapse preference. Unscheduled/invalid tasks reveal their row without navigating time.

**Quick Edit** reuses the task Name/Start/End editor in reserved space within the expanded details. Invalid/reversed dates remain visible for correction, with an error message. Save makes an ordinary canonical edit and triggers recalculation; Cancel leaves dates unchanged. Undo/Redo restores committed schedule edits and recalculates. Open Task navigates to standalone Tasks. Small panes can scroll vertically to reach editor controls.

## Chart visibility and filters

Gantt and Tube Map each have an independent **Critical Path** checkbox, off when opening a project. A navy outline and contextual legend identify reliably critical items while preserving normal status fills. Chart highlighting always uses project-wide criticality, even when Analysis is scoped to a stream. Display toggles are transient, not persisted calculation data.

Gantt's Search/Filter popup includes **Hide Empty Streams**, **Hide Unscheduled Tasks**, **Hide dependencies** and **Task Status**. Hide Unscheduled defaults off and excludes missing, invalid and reversed task schedules when enabled. An Analysis selection can temporarily reveal an excluded task without unchecking the filter. Clear all resets it. Empty-stream filtering evaluates remaining chart content and preserves milestone behavior.

Tube Map uses the same compact popup width, padding, checkbox spacing and headings, with **Hide Empty Streams**, **Hide dependencies** and **Milestone Status**. Popup height follows its option count. Dependency visibility remains synchronized with each chart's Dependencies checkbox.

## Refresh, failures and CSV

Relevant committed edits automatically recalculate in the background. Previous results are marked outdated during recalculation and are not used for chart highlighting or CSV. Use **Refresh** to request fresh results. A calculation failure shows **Unavailable** and **Retry**, while ordinary project editing and file operations remain available.

**Export CSV** downloads every active task in the selected calculation scope, including unresolved/unscheduled tasks and rows hidden by display filters. It includes planned/calculated dates, criticality, float and reliability. Unreliable values remain blank. This is a local generated report; it does not change the project or store calculations in `.pmp`.

# Compatibility and acceptance scope

PMP container format 1/schema 2 and supported legacy files remain compatible; no v1.7 migration is introduced. Files with baselines retain the established v1.6 minimum-reader requirement. Calculated results, selection and chart toggles are not persisted, audited or added to Undo history. No `.mpp` conversion, cloud synchronization or automatic scheduling is provided.

The owner reported **macOS local UAT passed for the reported v1.7 UI fixes**. Full-feature v1.7 UAT, complete native-file permission scenarios, Windows testing and UAT of these subsequent remediation changes are not claimed. Automated Linux/Chromium results are recorded separately in the release-readiness register. The candidate is not tagged, published or deployed.
