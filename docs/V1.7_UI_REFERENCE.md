# Read this first

This manual describes **ARGOS PM Version 1.7.0** on `main`, including the consolidated UI and Tube Map correction merged in PR #34 (`9266a02`). Open it in **Settings → UI Reference Manual**. The application still labels its bundled v1.7 manual as a release candidate because no v1.7 tag or release was created by that merge. This guide describes implemented behavior; historical screenshots and demonstrations are identified separately.

ARGOS PM is a local-first project workspace for desktop Chrome on macOS and Windows. The self-contained `.pmp` file is the source of truth. No account, external database or online calculation service is needed. Keep a separate untouched copy of valuable files before cross-version testing.

## Start, open and create

Run the local application and use **New Project** or **Open Project**. A new project requires Name, Start date and an explicitly selected Status. Description and End date are optional. Complete required fields, choose **Choose File & Create**, select a local filename and grant browser write permission. Cancelling a picker does not create a project. Corrupt and incompatible project files are rejected with a clear error; required technical migrations preserve the original file.

## Save, switch and close

The sidebar shows the project name and a save-status dot. Green means saved, amber means unsaved, a pulse means saving (subject to reduced-motion preferences), and red means a save/access problem. Hover or focus the dot for details. Reveal the floating **Project actions** toolbar at the top-right by hovering over the thin top-edge strip for 300ms, or press **Alt+Shift+T**. It contains save status, **Save Now**, **Undo** and **Redo**; Escape closes it and restores keyboard focus. Autosave checks dirty state every 60 seconds. **Settings** provides **Open Project**, **Close Project** and **Save As**. Dirty close/switch presents Save, Discard and Cancel; a failed save keeps work in memory. Retry after restoring access or use Save As. When a file changed externally, review Keep Current or Reload from File before overwriting anything. Saved timestamps retain the original saving device's timezone information when available. Chrome controls file consent and does not disclose the full folder path.

## Sidebar and project settings

Open a page by selecting it in the sidebar. Collapse/expand animates the sidebar and workspace together; reduced motion removes that transition. The save dot remains visible in the collapsed rail. With a sidebar page button focused, Up/Down navigates without wrapping; Tab moves to that page's Search or first main control. Shift+Tab retains normal browser order.

Open **Settings → Project Details** to edit project name, description, dates, status and **Show progress information**. The editor is no longer opened from Overview. Settings also keeps file metadata, file actions, the local manual and the optional **Audit Log (Experimental)**. Audit records are hidden until requested, retain the existing 50-row viewer, filters, sorting, CSV export and retention controls.

## Records, search and history

Use the sidebar to open Streams, People, Tasks, Milestones, Risk Log and Decision Log. **Add** opens the shared right-side form. Fields marked with an asterisk are required. Use Create to commit, Cancel to discard, and the normal inline/context editors to update existing records. Task hierarchy, people/owners, scopes and relationships remain part of the canonical project. Deleted records are distinct from active records; use the appropriate page's Show Deleted controls when available.

Each page has live Search and an adjacent filter button. Search is live and combines with selected filters. Categories combine with AND; multiple values in a category combine with OR. Clear all resets search and filters. Click column headings to sort. Search/filter and chart-selection states do not change project data. In global Search, activate a result title to open its owning page and temporarily reveal, focus and highlight the record, including a record excluded by destination filters. Returning to Search restores its query, filters, result scroll and focus within the same project session. Baseline results open their entry in Manage baselines without changing comparison selection; dependency results target the relationship. Warnings use direct record/relationship navigation too. Escape or interaction outside the target clears the temporary reveal. Warnings are informational; review the record or relationship before making an explicit correction. Risk Matrix and context controls retain their normal behavior.

Undo and Redo operate on committed edits. Optional Audit Log recording is controlled in **Settings**, retains a bounded recent history and offers CSV. Recording does not replace the project file or provide a backup. Native keyboard focus and control behavior follow the browser; labelled controls support keyboard use.

# Working through a project

## Overview

Overview summarizes active tasks, upcoming/delayed milestones, risks and the high-level timeline. **Quick Actions** opens the existing creation flows. The Critical Path shortcut opens Extended Gantt directly at Analysis.

When **Show progress information** is enabled in Project Details, **Project Progress (manual)** appears with a bar and a percentage input. Enter a whole value from 0 to 100; valid values commit immediately. Empty/intermediate/invalid drafts do not save an invalid percentage. This is a project-level manual value, separate from calculated task/stream progress. Hiding the card preserves the dashboard's column order. The Timeline stays beside the left stack on desktop.

## Streams and People

Create Streams for work areas and People for owners. Edit the normal table controls; searchable owner/scope selectors accept names and human-readable IDs. Stream dates/status/ownership and People contact/notes fields retain their normal validation. Notes can be resized. Use Show Deleted where available to find and restore removed records. Review any reassignment or relationship confirmation before deleting a referenced record.

## Tasks

Create tasks from Tasks or Extended Gantt. Assign an owner and a stream or Project-wide scope, then enter dates/status and optional relationships. The hierarchy supports four levels. Parent progress/status/dates are derived from children; edit the appropriate leaf task rather than expecting a parent override. The task-only Tentative status remains available. Completing/reopening records follows the existing actual-completion rules.

Dependencies are explicit relationships and never automatically move planned dates. Use the task's relationship controls to create links and Dependencies to inspect/edit existing links. Select rows for supported bulk deletion; confirmations, Undo/Redo and restoration remain available. Duplicating creates a new identity while the brief feedback highlights its source row.

## Milestones

Milestones are dated stations shared by the table, Gantt and Tube Map. Choose Project-wide or one/more streams, plus the normal status/owner and task/dependency links. The Scope summary shows its first active selected stream and **+N** for additional active streams; activating either opens the same scope selector. Deleted-stream fallback labels remain available. Dependency warnings sit in an external gutter beside equal-width controls. Edit the table or a current chart station; historical baseline markers cannot be edited.

## Risk Log and Decision Log

Risk Log keeps probability, impact, derived severity, owner/status, due date, context and optional Risk actions. Toggle the Risk Matrix, select cells to filter, and use its normal search/status/scope controls. The matrix's visibility is session-only. Open **Actions** for action details/counts and **Context** for related records. Decision Log retains title, date, owner and context/rationale; it does not introduce a decision status field.

## Shared actions and tooltips

Compact row controls use a message bubble for Context, lightning bolt for Actions (including zero counts), copy for Duplicate, pencil for Inspect/Edit and trash for Delete. Hover or focus to read the action label. Successful Duplicate briefly highlights the source row; successful Delete briefly marks the vacated boundary. Each lasts about 600ms, respects reduced motion and does not appear for a cancelled/failed action. Confirmations and Undo/Redo are unchanged.

On non-chart pages, repeating-name tooltips appear only when text is clipped. Explanatory and action tooltips remain available. Chart details retain rich hover/focus behavior regardless of caption clipping. Dialogs, baseline lists and embedded editors share compact controls; validation, keyboard focus and dismissal behavior are preserved.

# Planning workspace and baselines

## Fit the workspace

Desktop record pages retain continuous table headings and aligned fields. On genuinely narrow workspaces, supported record fields wrap into labelled groups; Extended Tasks keeps its continuous row layout with every column visible. No fields or actions are removed: use vertical scrolling to reach the last record. The sidebar keeps all navigation entries visible without its own scrollbar and can still collapse. Gantt and Tube Map move through time with Previous, Next and Jump to today, rather than horizontal scrolling.

## Baselines

Open **Baselines** in the sidebar. Open the ellipsis actions menu beside the selected baseline in the title/Search toolbar and choose **Create baseline**, enter a required name (up to 200 characters) and optional description (up to 20,000 characters), then Create. A baseline records active task and milestone dates, names, stable IDs and historical stream references at that moment. It does not copy risks, people, decisions, attachments or executable content. Renaming a task, editing dates or deleting a live entity never changes a saved historical schedule.

Create multiple named baselines to keep different commitments. The toolbar comparison selector chooses the baseline used across views. **Manage baselines** opens the complete dated/described list; **Rename** and **Delete** are available through the actions menu. Selection is session-only and defaults to the first baseline after reopening. Rename changes name/description only; Delete requires confirmation. Undo/Redo applies to creation, rename and deletion. Baselines remain available when audit recording is disabled.

The comparison table shows baseline and current start/finish dates, day variances, stream names, entity IDs/names and Matched/Added/Removed status. Positive variance means later, negative means earlier; zero means the same date. An unavailable date shows Undated and its variance shows —. Search, filters and sorting change the display immediately without editing data. Click any of the nine column titles to alternate ascending/descending order; keyboard activation is also supported. Dates sort chronologically and variances numerically, with missing values last. Removed means absent from the active current schedule, including soft deletion. Historical stream names remain available even when a live stream has been removed.

## Gantt baseline controls

Select a comparison baseline below the toolbar. **Baseline overlay** shows muted dashed historical task bars and hollow milestone diamonds alongside the live schedule. A red dashed segment identifies a later current finish. Hover or keyboard-focus the historical shape for the item name and current/baseline start/end dates. The old **Variance indicators** checkbox and inline variance labels are removed; the Baselines table retains calendar-day variance calculations.

Use **Hide Dependencies** and **Show Critical Path** in Gantt's Search/filter popup; there are no separate Dependencies/Critical Path checkboxes in the chart toolbar. Clear all restores dependencies and turns the critical overlay off. Simple and Extended share these controls and the same dates. Compact stream/title and date-header bands do not move task or milestone dates. A warning triangle before a name opens the existing warning details.

## Tube Map comparison and names

Tube Map shows milestones as colored current stations on stream lines. It opens a Monday-aligned twelve-week window: four full weeks before the current week, the current week and seven following weeks. **Jump to today** restores that window. Previous/Next each move four weeks. **Axis** switches between week numbers and Monday dates. Stream/week headings occupy one compact header band.

Select a comparison baseline. The **Combined / Detached** radio group becomes available only when its captured milestone names/dates/scopes or stream identities/names differ from the live Tube Map. A task-only change does not enable it. Matching or missing snapshots show an explanation. Filtering or paging does not change that comparison decision.

- **Detached** (the below-map mode, and the default) shows historical milestones in a strip beneath the live map using the same date window.
- **Combined** shows hollow historical diamonds in the main map. Historical-only streams retain labelled lanes. Live station coordinates, status colors, dependencies and editing stay intact.

Open the filter popup for **Hide Empty Streams**, **Hide Dependencies**, **Hide Milestones Names**, **Show Critical Path** and **Milestone Status**. Names default visible; Hide Milestones Names hides both live and historical captions while keeping names in accessible details. Ordinary live lanes compact from 88px to 48px; same-day stations may need extra rows. Clear all restores names/dependencies, clears status/empty-stream filtering and turns off the critical overlay.

Hover or keyboard-focus a current or historical marker for one application tooltip. Historical details identify the milestone name/ID, baseline/current dates, scope and available variance. Historical status is explicitly **Not captured in baseline**; current status is shown separately where available. Coincident historical milestones are grouped without losing their individual details. Tooltips stay within the viewport, can be hovered and dismiss with Escape; no native duplicate tooltip is used.

In Combined mode a historical target that collides with a current button/caption moves to the nearest clear horizontal position. Its stored date anchor, dates and dimensions stay unchanged, and placement recalculates on resize. This keeps the historical target accessible even when two live milestones share one date and names are hidden. Current diamonds remain 26px editing targets and historical targets remain 18px. Click a current diamond/caption, or focus it and press Enter, for Quick Edit. Save edits the live record only; Cancel leaves it unchanged. The editor stays above the sticky footer. Historical markers are read-only.

## Dependencies

Open **Dependencies** for a project-wide relationship list. Search by item, stream, relationship type or warning; filter to cross-stream links, warnings and supported types. Sort by predecessor, successor, type, streams or warning count. Cross-stream means both endpoints have assigned scopes with no shared stream; Project-wide is an explicit scope, and unassigned items cannot establish a cross-stream classification.

Choose **Inspect / Edit** to change predecessor, successor or type on the existing relationship. Dynamic endpoint selectors are searchable and show stable human-readable IDs. Self-links, cycles, duplicate endpoint/type combinations and invalid/deleted new endpoints prevent saving. The relationship retains its original stable ID. Create new links using the existing Tasks/Milestones controls.

Finish-to-Start, Start-to-Start, Finish-to-Finish and Start-to-Finish values are retained and inspected. Schedule conflict warnings compare the corresponding start/finish dates; missing dates/references and deleted endpoints are reported. Warnings are informational, recalculate after edits and never move dates. Existing chart-specific connection support remains unchanged.

## Project files and history

All baseline data lives inside the same `.pmp` file, behind the existing Project File Service. Existing v1.4/v1.5 files open without a new technical schema migration and preserve their data on save/reopen. A file containing baselines declares a minimum v1.6 runtime to protect historical data from older readers. Preserve the original file if you need to continue using an older application. No automatic downgrade or cloud storage is introduced.

Snapshot schema version is 1; the existing project schema remains 2 and PMP container format remains 1. The parser validates historical IDs, dates, scope references and collection bounds. Baseline collections have a 1,000-entry safety bound and existing archive/entry limits still apply. Comparison uses calendar days independent of daylight saving time. Audit recording remains optional and independent of baselines; baseline collection/metadata changes are recorded when audit is enabled.

## Gantt Extended Mode

Choose **Extended** immediately before Expand All to display the compact Gantt above the Tasks workspace. Choose **Simple** to return to the full-height chart. The standalone Tasks page and Simple Gantt keep their standard spacing. Task fields, actions, filters, sorting, creation, deletion/restoration and dependencies use the same existing module and canonical project data.

The two Search fields stay centered on the full page content at the same horizontal position as other pages. Each pane has independent vertical scrolling. Gantt date headings and navigation remain accessible; Tasks keeps its own sticky toolbar/headings. Status colors are unchanged. Baseline overlay, comparison selection and filter-controlled dependency/critical visibility work in both modes.

Drag the horizontal separator to resize the panes. Keyboard users can focus the separator and press Up/Down to move it by 16px, or Shift+Up/Down by 64px. Both panes retain usable minimum heights; shorter windows allow outer vertical scrolling. The split and selected mode are session-only and return to Simple after closing/reopening the project.

**Add Task is exactly the existing standalone Tasks creation panel**: same size, page-level right-edge position, field distribution, whitespace, fonts, required/optional fields, validation and keyboard behavior. The full-height panel overlays both panes. Only its form body scrolls; its header and Create/Cancel footer remain available. The compact pane styles do not apply to the panel. Escape/outside dismissal of a populated draft asks Stay/Discard; Cancel discards immediately, as on standalone Tasks.

Both panes update together. Task quick edits, creation and deletion participate in the existing Undo/Redo and optional audit history. Live edits never modify immutable baselines. Switching mode preserves each pane's search/filter state. No automatic scheduling is introduced.

This v1.7 guide covers inherited module operations as well as current enhancements. Versioned v1.5/v1.6 manuals remain available for users running those versions; their screenshots and demo footage are historical.


## Safe save limits and historical stream names

Saving checks the same 16 MiB per-entry and 32 MiB total archive limits used when opening files, including UTF-8 byte sizes and container overhead. If accumulated history exceeds these limits, saving fails before a file writer is opened. The prior successfully saved file remains unchanged and reopenable; current edits remain in memory. Remove unneeded baselines using the normal confirmed deletion flow, or reduce project content, before retrying. History is never pruned automatically.

The comparison table uses historical stream names for baseline associations and current names for live associations. If a stream is renamed or an entity moves, both values are shown when they differ. Removed items retain their historical names. Search matches the appropriate historical/current names, and stream filters display both names for renamed IDs.

## Compact rows and direct warning navigation

Record tables reserve the ID/name space above the field band and keep a small lower inset. Headings use a shorter band; scope fields retain their accepted layout, with Milestones using a fixed single-line first-stream/+N summary. Notes remain editable and vertically resizable.

In Warnings, click the warning title, entity information or description to open the related module and targeted record. Keyboard users can focus that same content and press Enter or Space. The separate Open button is removed; explicit corrective actions still require their established confirmation.

Dependencies uses the shared compact typography and row rhythm. Hover over abbreviated entity, scope or warning text to inspect the full value; Inspect / Edit retains the complete relationship and warning information. Search/filter/sort still matches full values. Gantt Search now uses the standard 340px size and the same centered position/fallback as ordinary pages. At narrow widths, the standard Search row appears below the title/actions instead of shrinking the search field.

Milestone dependency warning indicators sit beside the predecessor field on the same control band. Click or focus the indicator to open the existing measured warning popup; Escape dismisses it without changing dates or relationships.

## Compact controls and comparison lists

Record fields, dialogs, popovers and embedded Tasks use the accepted compact control styling without removing fields, reducing text size or changing validation. Predictive dropdown searches show **Type to filter**. Longer descriptions and genuinely expanded lists scroll inside their existing form/list region.

Manage baselines shows equal-height rows with name/timestamp and a single-line description; hover or focus a clipped description for its full text. Rename/Delete are compact icons. The list scrolls above Create baseline/Done. Create/Rename use required Name and optional Description. Comparison rows show ID and saved name without a redundant type suffix.

Baselines and Dependencies retain full values, live search/filter/sort, compact headings and accessible actions. Clipped text uses the shared application hint. Missing dates/variance sort last; active sort direction remains visible. Dependencies keeps its results scroller above the docked footer, so the last row is reachable.

## Timeline focus, dates and navigation

Gantt and Tube Map use dotted grey dependency connectors by default. Hover or keyboard focus previews one relationship; click or press Enter/Space to pin it. Selecting a different connector replaces the selection. Press Escape or activate the pinned relationship again to clear it. Only the relationship endpoints keep their status colors while unrelated Gantt tasks/milestones or Tube Map milestones turn grey. These are display states and do not edit a relationship or the project.

Open either chart's Search/filter panel and choose **Hide Dependencies** to remove all relationship lines. There is no separate Dependencies checkbox; **Clear all** restores dependency visibility. Smooth connectors retain a successor arrow and a readable relationship description.

Both charts share compact legend/navigation footer geometry and ordinary button typography. Gantt keeps its Zoom control in that footer. Gantt day headings and Tube Map Monday-date headings display centered **DD/MM** values; footer ranges show **DD/MM/YYYY**. Tube Map's **Axis** selector retains its alternative week labels. Date-navigation increments remain specific to each chart.

## Compact record creation

Add/Create opens the shared right-side drawer with a maximum width of 560px and two main columns. Task descriptions span the drawer width and the original adjacent Task field pairs are retained. The accepted compact control and spacing recipe reduces empty space without introducing a smaller font. All six initial forms and Create/Cancel fit supported desktop windows, including short laptop windows.

Validation remains real: required fields are marked, errors stay associated with controls, and actual messages expand naturally. Header and Create/Cancel remain visible. A narrow screen, an expanded multi-action Risk list or user-expanded multiline content may scroll only inside the form body. The same Task drawer is used from standalone Tasks and Extended Gantt. In Risk creation, an empty Risk actions control may share the Due date row; actual action lists use the full form width.


# Critical Path Analysis

## Enter Extended Mode

Open **Gantt**, then select **Extended** immediately before Expand All. The chart remains above a resizable divider. The lower pane offers compact **Tasks** and **Critical Path Analysis** tabs. Entering Extended Mode normally opens Tasks; the Overview Critical Path shortcut deliberately opens Analysis. Returning from Simple Mode opens Tasks again.

Use Left/Right arrows or Home/End on the tabs; the active tab has a distinct border and visible focus. Use the divider with pointer dragging or its Up/Down arrows (Shift for larger steps). The panes scroll independently. The full Task creation drawer remains the same as standalone Tasks.

## Scope, results and reliability

Project-wide is the default calculation scope. Select a stream in the Scope control for stream-relative results; cross-stream dependencies remain part of the calculation. Display search and stream/critical-status filters do not recalculate the mathematical scope. The calculation uses Project Start, inclusive calendar-day task durations, all four supported dependency types and zero-duration linked milestones. Calculated dates respect dependencies and are separate from planned dates. Same-day Finish-to-Start is supported. Planned dates, baselines and canonical relationships are never automatically changed.

The summary shows critical-task count, distinct critical-path count and calculated completion. The table shows calculated start/finish, Critical/Noncritical/Unresolved/Unscheduled and total/free float. Sort headings normally. Expand a row for planned versus calculated dates, latest dates, reliability, relationships and warnings. Expand All/Collapse All affects details in the calculation scope.

**Up to date** means calculations completed. **Partial** means input or planned-schedule issues need review; reliable portions can still be shown. A provisional completion is labelled explicitly. Unreliable float and criticality remain blank rather than invented. Cycles and affected downstream activities are unresolved; unrelated reliable dates can remain available. Missing, invalid or reversed planned dates are **Unscheduled** and remain discoverable with that filter. Add or correct dates through Quick Edit; classification alone never repairs a schedule.

Linked milestone scheduling warnings appear in the related task's expanded details, labelled with the milestone identity. Their descriptions and warning identities are shared with the Warnings page; opening details does not create additional warning records. Review the relationship in Dependencies and edit the intended record explicitly.

## Select, reveal and correct

Select a task's name in Analysis to reveal its Gantt row, navigate to its date window if scheduled and temporarily highlight it. The chart scrolls only when needed; the analysis pane and page remain stationary. Search/status filters and sort preferences stay set. A hidden task is temporarily revealed, including within a collapsed stream. The stream's disclosure reports its actual expanded display; Escape clears the reveal and restores the user's collapse preference. Unscheduled/invalid tasks reveal their row without navigating time.

**Quick Edit** reuses the task Name/Start/End editor in reserved space within the expanded details. Invalid/reversed dates remain visible for correction, with an error message. Save makes an ordinary canonical edit and triggers recalculation; Cancel leaves dates unchanged. Undo/Redo restores committed schedule edits and recalculates. Open Task navigates to standalone Tasks. Small panes can scroll vertically to reach editor controls.

## Chart visibility and filters

Gantt and Tube Map each have an independent **Show Critical Path** checkbox in the Search/filter popup, off when opening a project. A navy outline and contextual legend identify reliably critical items while preserving normal status fills. Chart highlighting always uses project-wide criticality, even when Analysis is scoped to a stream. Display toggles are transient, not persisted calculation data.

Gantt's Search/Filter popup includes **Hide Empty Streams**, **Hide Unscheduled Tasks**, **Hide Dependencies** and **Task Status**. Hide Unscheduled defaults off and excludes missing, invalid and reversed task schedules when enabled. An Analysis selection can temporarily reveal an excluded task without unchecking the filter. Clear all resets it. Empty-stream filtering evaluates remaining chart content and preserves milestone behavior.

Tube Map uses the same compact popup width, padding, checkbox spacing and headings, with **Hide Empty Streams**, **Hide Dependencies**, **Hide Milestones Names**, **Show Critical Path** and **Milestone Status**. Popup height follows its option count. Dependency visibility is controlled by Hide Dependencies in that chart's popup.

## Refresh, failures and CSV

Relevant committed edits automatically recalculate in the background. Previous results are marked outdated during recalculation and are not used for chart highlighting or CSV. Use **Refresh** to request fresh results. A calculation failure shows **Unavailable** and **Retry**, while ordinary project editing and file operations remain available.

**Export CSV** downloads every active task in the selected calculation scope, including unresolved/unscheduled tasks and rows hidden by display filters. It includes planned/calculated dates, criticality, float and reliability. Unreliable values remain blank. This is a local generated report; it does not change the project or store calculations in `.pmp`.
