# ARGOS PM v1.7 — approved requirements

D01–D68 below reproduce the owner-supplied consolidated planning document. D69–D74 and UI-01–UI-03 were explicitly approved subsequently in the planning conversation. The owner finally approved implementation after the pre-implementation plan. Earlier planning-only instructions in the uploaded document do not constitute current implementation restrictions.

The approved scope supersedes the v1.6 critical-path exclusion only for this release. No permission to merge, publish or deploy is implied. UI concepts A–D were finally approved subject to the mandatory requirements below. Existing v1.6 component patterns remain authoritative for presentation.

## D01–D68

**D01 — Hybrid recalculation.** Automatically calculate critical paths after relevant committed changes; retain manual Refresh; never alter planned dates.

**D02 — Scope.** Support project-wide and per-stream critical path calculations, respecting cross-stream dependencies.

**D03 — Scheduled task coverage.** Include all active scheduled tasks, including tasks without dependencies.

**D04 — Duration calendar.** Use calendar days, including weekends.

**D05 — Chart toggles.** Provide optional Critical Path toggles in Gantt and TubeMap, without changing existing views when off.

**D06 — Float.** Calculate total float and free float for eligible tasks.

**D07 — Partial calculation.** Calculate reliable portions of incomplete or inconsistent schedules; issue explicit warnings and never invent dates.

**D08 — Analysis location.** Use a collapsible Critical Path Analysis panel within Gantt; do not add a separate page or Tasks columns.

**D09 — Extended Mode lower panel.** Gantt remains on top; the lower pane shows either Tasks or Critical Path Analysis, never both; divider is resizable; existing Tasks functionality preserved.

**D10 — Recalculation triggers.** Recalculate after valid committed changes, batch rapid edits, not while typing; retain manual Refresh.

**D11 — Parallel paths.** Identify all critical paths, including parallel critical sequences.

**D12 — Current schedule.** Calculate against current schedule only; do not compare historical baseline critical paths.

**D13 — Milestones.** Treat linked milestones as zero-duration scheduling events; unlinked milestones informational; verify actual model support.

**D14 — Visual design.** Preserve existing status colours; use subtle critical indicators; require mockup approval.

**D15 — Analysis controls.** Provide search, stream/critical-status filtering and sorting using existing UI patterns.

**D16 — Persistence.** Derive results dynamically in memory; do not persist results or caches in .pmp; preserve compatibility.

**D17 — Calculated schedule.** Derive dependency-consistent dates in memory without modifying planned dates; flag conflicts.

**D18 — Relationship types.** Use all relationship types supported by existing model (FS, SS, FF, SF where supported); flag invalid or unsupported.

**D19 — Lag/lead.** Use stored lag/lead if present, otherwise zero; no new editing fields; verify actual schema.

**D20 — Critical classification.** Classify critical tasks only, not near-critical; compute float for all eligible tasks.

**D21 — Overview summary.** Add compact Project Overview summary: critical tasks, critical paths, calculated completion and partial-results indicator; mockup approval.

**D22 — CSV export.** Export task IDs/names, stream, dates, critical status and total/free float as local CSV.

**D23 — Warnings.** Show warnings in analysis and existing Warnings page without duplicate records or counts.

**D24 — Task selection.** Synchronise analysis-row and Gantt task selection, preserving current search/filter/sort.

**D25 — Independent toggles.** Gantt and TubeMap critical visibility toggles are independent but use shared calculated data.

**D26 — Default toggles.** Both chart critical toggles are off by default when a project opens.

**D27 — Extended default.** Extended Mode initially opens with Tasks as the lower pane; Critical Path Analysis is manually selected.

**D28 — Responsive processing.** Use non-blocking calculations/background processing as needed; show subtle progress and discard outdated results; local only.

**D29 — Failure handling.** Keep project usable after calculation failure; show Unavailable and Retry; never change project data.

**D30 — Status indicators.** Use Calculating, Up to date, Partial, Unavailable; Overview only displays exceptional Partial/Unavailable status.

**D31 — Undo/Redo.** Recalculate after relevant Undo/Redo; do not add calculation history entries; batch and discard superseded results.

**D32 — Cycles.** Isolate circular dependency chains; calculate unaffected portions; Partial with actionable warnings; never alter links.

**D33 — Completed tasks.** Include completed tasks based on planned dates; preserve dependency continuity; no new actual-date fields.

**D34 — Reliable highlighting.** Highlight only reliable critical paths in Partial results; unresolved items visually distinct and unclassified; retain status colours.

**D35 — Partial CSV.** Export all eligible tasks with calculation status; blank unreliable calculated values; keep planned dates and identities.

**D36 — Empty states.** Distinguish no tasks from insufficient scheduling information; show actionable guidance without fabricated results.

**D37 — Completion date.** Project completion is latest reliable dependency-consistent finish across eligible tasks/linked milestones; provisional when unresolved data could affect it.

**D38 — Negative float.** Show negative float with subtle warning styling; explain via existing warnings without duplicates; do not automatically classify as critical.

**D39 — Quick Edit.** Reuse existing task Quick Edit in analysis panel; row selection still syncs Gantt; recalculate on commit.

**D40 — Deleted tasks.** Exclude deleted tasks from calculations, counts, highlighting and CSV; warn on active links to deleted items; Partial if reliability affected.

**D41 — Filter semantics.** Stream display filters do not change project-wide criticality/float; separate per-stream calculation scope remains available.

**D42 — Scope selector.** Provide explicit Project-wide/Per-stream analysis scope selector independent of filters; respect cross-stream dependencies.

**D43 — Default scope.** Project-wide is the default when opening Critical Path Analysis.

**D44 — Default ordering.** Sort by calculated start ascending then stable task ID; unresolved dates last; allow user sorting.

**D45 — CSV scope.** Export all eligible tasks in selected calculation scope, ignoring temporary search/display filters; include unresolved, exclude deleted.

**D46 — Chart criticality.** Chart highlights always use project-wide criticality, independent of analysis scope; chart toggles independent.

**D47 — Unscheduled tasks.** Show active unscheduled tasks at bottom as Unscheduled, without calculated dates/float/criticality; warn on affected links; Quick Edit available.

**D48 — Planned/calculated dates.** Show both planned and calculated start/finish in analysis (main or expanded details); subtly flag differences; never alter planned.

**D49 — Compact table.** Use compact table with expandable task details; main row identification, calculated dates, criticality and float; planned dates/secondary info in details; no horizontal scrolling; mockup approval.

**D50 — Default row expansion.** Details collapsed by default; independent row expansion; no recalculation on expand.

**D51 — Bulk expansion.** Provide Expand All/Collapse All across current analysis calculation scope, not merely currently filtered rows.

**D52 — Shared divider.** Use same resizable divider for Tasks and Critical Path Analysis; preserve position when switching lower panels.

**D53 — Simple Mode.** Analysis panel available only in Gantt Extended Mode; Simple Mode unchanged except critical toggle.

**D54 — Mode return.** Always return to Tasks lower panel when re-entering Extended Mode.

**D55 — Scope switching.** Update analysis immediately using available in-memory results; avoid unnecessary recalculation.

**D56 — Stale results.** Mark previous results outdated until recalculation completes.

**D57 — Scrolling.** Independent vertical scrolling in lower analysis panel with sticky table headers.

**D58 — Contextual legend.** Show compact contextual legend only when critical highlighting is enabled.

**D59 — Task navigation.** Selecting analysis task jumps to its Gantt location and temporarily highlights it.

**D60 — Summary metrics.** Show critical task count, critical path count, calculated completion date and calculation status in summary.

**D61 — No critical path.** Show contextual No critical path identified message with calculation status.

**D62 — Search behaviour.** Use live contains-search consistent with ARGOS PM.

**D63 — Keyboard accessibility.** Reuse existing keyboard/focus standards for rows, expansion, Quick Edit and controls.

**D64 — Testing strategy.** Deterministic unit tests plus targeted integration and end-to-end tests; avoid exhaustive redundant E2E.

**D65 — File compatibility.** Maintain backward compatibility with existing .pmp files; no migration required.

**D66 — Technical diagnostics.** Keep technical diagnostics available for development/testing only, not in normal UI or project files.

**D67 — UI approval gate.** Require mockup approval before implementing new analysis panel and chart indicators.

**D68 — Release acceptance.** Require calculation accuracy, partial results, UI approval, regression tests, compatibility checks and documentation before release.

## D69–D74

- **D69 A:** Preserve existing same-day Finish-to-Start semantics.
- **D70 A:** Use Project Start as the common scheduling anchor; planned dates remain comparison values.
- **D71 A:** Calculate stream-relative float using the full project dependency graph.
- **D72 A:** Count distinct maximal critical sequences, deduplicating parallel dependency records.
- **D73 A:** Track reliability separately for dates, float and criticality; withhold unreliable values.
- **D74 A:** Temporarily reveal the selected task without changing filters, search or sorting.

## Mandatory UI conditions

- **UI-01:** Quick Edit must not overlap details or clip on smaller laptop viewports; reuse viewport-aware existing editor behaviour. In the analysis pane it occupies a reserved slot; vertical scrolling keeps controls accessible in small panes.
- **UI-02:** Gantt and TubeMap Critical Path toggles are independent and off/unchecked when opening a project. They remain available to the user.
- **UI-03:** Overview summary navigates directly to Gantt Extended Critical Path Analysis through existing guarded navigation. Clearly distinguish provisional completion and unresolved counts from reliable results.

Preserve the sidebar, page titles, centered search, toolbar conventions, status colours, original Tasks creation panel, baseline functionality, planned dates, offline operation, .pmp compatibility and audit semantics.
