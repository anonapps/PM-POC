# PM-POC v1.4 — Approved enhancement implementation plan

Status: Approved for implementation on `feature/v1.4-approved-enhancements`. Do not merge into main without explicit user approval.

## Decisions
- Quick edits use compact anchored popovers.
- Gantt streams start expanded; support per-stream and all-stream toggles.
- Audit history is optional, off by default, embedded in .pmp, capped at 5,000 events per project.
- Undo and Redo each generate explicit audit events when audit is enabled.
- All existing project data and UI functionality must remain intact.

## Phase A — UI foundations (E03, E04, E05, E06, E09)
- Sidebar: house and search icons; Tasks > Gantt > Milestones > Tube Map order.
- Risk level chips reuse matrix colour tokens (Low/Medium/High).
- Shared deterministic, accessible, typed column sorting for meaningful headers across tables and timeline. Preserve sorting and row identity when editing; missing values last.
- Desktop-responsive widths; no sidebar overlap or clipped actions; local table overflow when necessary.
- Gantt/Tube Map horizontal trackpad and scrollbar support, with sticky item column and retained navigation buttons.
- Overview Timeline: sortable columns, DD/MM/YYYY, label "Planned Project Duration".
Acceptance: sorting toggles in each applicable section, accessible sort direction; responsive widths and scroll across sidebar states; no regressions.

## Phase B — Visual editing (E01, E02)
- Gantt: click task -> anchored popover with name, start/end dates and Open in Tasks; stream click navigates to selected Stream; project-wide is not a stream entity.
- Tube Map: milestone diamond/label -> popover with name/date and Open in Milestones; stream name navigates to selected Stream.
- Cross-section navigation scrolls to and highlights the correct stable-ID row. Maintain context after sorting/filtering.
- Gantt per-stream expand/collapse; expanded by default; optional Expand All / Collapse All.
- All edits pass through canonical application commands and existing validation/undo/dirty tracking.
Acceptance: edits reflect across sections immediately; navigation selects correct record; no accidental mutations or broken dependencies.

## Phase C — Data and preferences (E07, E08)
- Edit Project contains "Show progress information", default true on existing projects. Hiding removes all progress inputs, badges and bars without mutating stored values or derived calculations; re-enabling restores values; save in .pmp.
- Person receives optional role and notes fields; editable only after person creation, only shown in People. Persist empty strings or optional fields compatibly.
- Inspect actual .pmp schema and follow existing explicit migration policy; original files must not be modified during migration.
Acceptance: existing files open under documented compatibility rules; roundtrip values survive save/reopen and Undo/Redo.

## Phase D — Experimental audit history (E10)
- Off by default, toggle in File Information.
- Store a bounded append-only logical event sequence in .pmp; include timestamp, operation, entity ID/type, changed fields and old/new values; record creation, duplication, soft deletion/restoration, rename/date edits, risk probability/impact plus resulting risk level.
- Capture committed application commands (not every keystroke), coalesce typing; never log autosave or derived rerenders.
- Record Undo/Redo as separate events, never silently rewrite previous audit entries.
- File Information offers searchable/sortable chronological viewer and manual CSV export. Escaping must protect CSV against spreadsheet formula injection.
- Cap to most recent 5,000 events; show retention limitation in UI. Turning off tracking retains existing events.
- Audit history is not a backup and cannot reconstruct prior project versions.
Acceptance: event accuracy, bounded size, disabled-path performance, export safety, persistence, undo/redo semantics.

## Delivery gates
1. Inspect existing components, command system, schema and tests before implementation.
2. Implement in four small reviewable commits/PR phases on the feature branch.
3. Run npm ci, npm test, npm run typecheck, npm run lint, npm run build, npm audit --omit=dev --audit-level=moderate, npm run test:regression and applicable lifecycle/e2e checks.
4. Add focused tests for each enhancement, schema compatibility, audit performance and event retention; preserve 30-record-per-module fixtures.
5. Update docs/PROJECT_REQUIREMENTS.md, docs/ARCHITECTURE.md, docs/IMPLEMENTATION_PLAN.md and acceptance/regression documentation to reflect approved changes.
6. Open draft PR against main; do not merge, tag or deploy without explicit user approval.
