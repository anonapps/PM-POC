# ARGOS PM v1.6 UI Reference — development candidate

Version 1.6.0 is an unreleased development version. This guide supplements the complete v1.5 manual in `docs/V1.5_UI_REFERENCE.md`; established project, task, milestone, risk, decision, search, file and audit operations remain supported. Extended Gantt is implemented following conditional mockup approval; the existing Tasks creation panel is reused unchanged.

## Fit the workspace

Content fits the available desktop viewport. On narrower workspaces, record fields wrap into labelled groups. No fields or actions are removed: use vertical scrolling to reach them. Sorting controls remain above the records. Sidebar collapse and navigation retain their existing behavior. Gantt and Tube Map move through time with Previous, Next and Jump to today, rather than horizontal scrolling.

## Baselines

Open **Baselines** in the sidebar. Choose **Create baseline**, enter a required name (up to 200 characters) and optional description (up to 20,000 characters), then Create. A baseline records active task and milestone dates, names, stable IDs and historical stream references at that moment. It does not copy risks, people, decisions, attachments or executable content. Renaming a task, editing dates or deleting a live entity never changes a saved historical schedule.

Create multiple named baselines to keep different commitments. The comparison selector and named list select which one all views compare against. Selection is session-only and defaults to the first baseline after reopening. Rename changes name/description only; Delete requires confirmation. Undo/Redo applies to creation, rename and deletion. Baselines remain available when audit recording is disabled.

The comparison table shows baseline and current start/finish dates, day variances, stream names, entity IDs/names and Matched/Added/Removed status. Positive variance means later, negative means earlier; zero means the same date. An unavailable date shows Undated and its variance shows —. Search, filters and sorting change the display immediately without editing data. Removed means absent from the active current schedule, including soft deletion. Historical stream names remain available even when a live stream has been removed.

## Gantt baseline controls

Select a comparison baseline below the Gantt toolbar. **Baseline overlay** adds muted dashed historical bars or milestone markers alongside the live schedule. **Variance indicators** shows start/finish day differences for live rows. **Dependencies** toggles existing supported chart connectors. Week, Month and Quarter use the same historical calculations. Added/removed entities and offscreen historical dates remain available in the comparison table; the chart does not invent live rows for deleted entities. Quick edits, stream links, filters, collapse/expand, zoom and persistent date navigation continue to operate on the live project.

## Tube Map baseline controls

**Baseline milestones** adds a separate historical strip aligned to the visible date window below the live map. Hollow indicators show baseline milestone dates and preserve historical stream assignments. Hover or focus an indicator to read its milestone ID/name, historical date and current date. Coincident historical indicators share a date; the comparison table exposes all records individually. The separate strip preserves live station geometry, captions and quick-edit targets. **Dependencies** shows/hides milestone connections without deleting relationships.

## Dependencies

Open **Dependencies** for a project-wide relationship list. Search by item, stream, relationship type or warning; filter to cross-stream links, warnings and supported types. Sort by predecessor, successor, type, streams or warning count. Cross-stream means both endpoints have assigned scopes with no shared stream; Project-wide is an explicit scope, and unassigned items cannot establish a cross-stream classification.

Choose **Inspect / Edit** to change predecessor, successor or type on the existing relationship. Dynamic endpoint selectors are searchable and show stable human-readable IDs. Self-links, cycles, duplicate endpoint/type combinations and invalid/deleted new endpoints prevent saving. The relationship retains its original stable ID. Create new links using the existing Tasks/Milestones controls.

Finish-to-Start, Start-to-Start, Finish-to-Finish and Start-to-Finish values are retained and inspected. Schedule conflict warnings compare the corresponding start/finish dates; missing dates/references and deleted endpoints are reported. Warnings are informational, recalculate after edits and never move dates. Existing chart-specific connection support remains unchanged.

## Project files and history

All baseline data lives inside the same `.pmp` file, behind the existing Project File Service. Existing v1.4/v1.5 files open without a new technical schema migration and preserve their data on save/reopen. A file containing baselines declares a minimum v1.6 runtime to protect historical data from older readers. Preserve the original file if you need to continue using an older application. No automatic downgrade or cloud storage is introduced.

Snapshot schema version is 1; the existing project schema remains 2 and PMP container format remains 1. The parser validates historical IDs, dates, scope references and collection bounds. Baseline collections have a 1,000-entry safety bound and existing archive/entry limits still apply. Comparison uses calendar days independent of daylight saving time. Audit recording remains optional and independent of baselines; baseline collection/metadata changes are recorded when audit is enabled.

## Gantt Extended Mode

Choose **Extended** immediately before Expand All to display the compact Gantt above the Tasks workspace. Choose **Simple** to return to the full-height chart. The standalone Tasks page and Simple Gantt keep their standard spacing. Task fields, actions, filters, sorting, creation, deletion/restoration and dependencies use the same existing module and canonical project data.

The two Search fields stay centered on the full page content at the same horizontal position as other pages. Each pane has independent vertical scrolling. Gantt date headings and navigation remain accessible; Tasks keeps its own sticky toolbar/headings. Status colors are unchanged. Baseline overlay, comparison selection, variance and dependency visibility work in both modes.

Drag the horizontal separator to resize the panes. Keyboard users can focus the separator and press Up/Down to move it by 16px, or Shift+Up/Down by 64px. Both panes retain usable minimum heights; shorter windows allow outer vertical scrolling. The split and selected mode are session-only and return to Simple after closing/reopening the project.

**Add Task is exactly the existing standalone Tasks creation panel**: same size, page-level right-edge position, field distribution, whitespace, fonts, required/optional fields, validation and keyboard behavior. The full-height panel overlays both panes and the project header. Only its form body scrolls; its header and Create/Cancel footer remain available. The compact pane styles do not apply to the panel. Escape/outside dismissal of a populated draft asks Stay/Discard; Cancel discards immediately, as on standalone Tasks.

Both panes update together. Task quick edits, creation and deletion participate in the existing Undo/Redo and optional audit history. Live edits never modify immutable baselines. Switching mode preserves each pane's search/filter state. No automatic scheduling is introduced.

The complete v1.5 user reference remains bundled at `/manuals/1.5/ARGOS_PM_UI_REFERENCE.pdf` for established module operations; this candidate guide describes the v1.6 additions and current approval limitation.
