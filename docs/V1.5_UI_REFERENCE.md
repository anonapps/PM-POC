# Read this first

ARGOS PM is a local-first project workspace. Your `.pmp` file is the authoritative, self-contained project. This manual describes the implemented **1.5.0-rc.1** candidate. It does not authorise a release, deployment or publication. Candidate acceptance and supported-platform checks are tracked separately.

The PDF is bundled with this candidate and available from **File Information → UI Reference Manual**. It works from the local application without retrieving a release asset. Repository source: `docs/V1.5_UI_REFERENCE.md`. A PDF asset for a future approved GitHub Release remains a publication step, not something already published.

This is a text reference to actual controls. Historical v1.3/v1.4 screenshots and video are not substituted for current UI screenshots. No illustrative application screens have been fabricated.

# Start, create and open

Use desktop Chrome on Windows or macOS with local file access enabled. Browser permission prompts are controlled by Chrome and the operating system. The application does not require an account, external database or cloud project storage.

The launcher offers **New Project** and **Open Project**. New Project requires **Project name**, **Start date** and **Status**; fields marked `*` are required. Status starts with Choose status and must be explicitly selected. Choose File & Create stays disabled until all mandatory fields and dates are valid; invalid submissions never invoke file access. Description and End date are optional. Calendar dates must be valid; End date cannot precede Start date. Choose **Choose File & Create**, pick a local location and grant write permission. Cancel returns to the launcher; cancelling the file picker keeps the valid draft available without creating a project.

Choose Open Project and select an existing `.pmp` file. Invalid, corrupt or unsupported files are rejected with an error. Keep an untouched backup when testing older or valuable projects. There is no `.pmp`-to-`.mpp` conversion in this application.

# Save, switch and close

The header shows save state and **Save Now**, **Undo** and **Redo**. Save Now writes the active project. Autosave checks dirty state every 60 seconds while the application remains open. A Saved indicator means the application received a successful write result; a failed save leaves changes in memory and must not be treated as saved.

Open **File Information** for **Open Project**, **Close Project** and **Save As…**. Save As writes a separate selected file and makes it active. The original project remains separate. Chrome does not disclose the selected folder path to the application.

Opening or closing while dirty presents **Save / Discard / Cancel**. Save must succeed before continuing. Discard proceeds without writing unsaved edits; reopening the same file loads its saved contents. Cancel keeps the current project and changes. Cancelling a subsequent file picker keeps the active project available. A clean Close returns to the launcher without an unsaved-change prompt.

Save errors show a persistent warning and recovery controls. Use **Retry** or Save Now after restoring access, or **Save As** to choose another location. Repeated failures offer Save As. If the file changed externally, **Keep Current** accepts the current file baseline for a later explicit save; **Reload from File** replaces in-memory work after the unsaved-change confirmation. Never overwrite another person's changed file without reviewing it.

# File Information and timestamps

File Information shows file name, available file size, last successful save metadata, application version, manual links and Audit Log controls. Locate the physical file by name in Finder or File Explorer; the application cannot show its full folder path.

Last Saved uses the original saving device's local date/time, IANA timezone name and UTC offset. It is not converted to the viewing device's timezone. Compatible legacy files without timezone metadata display **Timezone unavailable** until a successful save adds the optional metadata. Failed writes do not advance the successful-save baseline.

The manual resolver chooses an exact version first. If no exact manual exists, only a same-major/same-minor manual at an available compatible patch is eligible, clearly labelled **Compatible same-minor fallback**. A v1.4 manual is never presented as compatible with v1.5. No available match produces an explanatory message rather than a broken release link.

# Navigation and workspace

Use the sidebar to open Overview, Streams, People, Tasks, Milestones, Gantt, Tube Map, Risk Log, Decision Log, Warnings, Search and File Information. The selected page is announced as current. Collapse/expand uses the sidebar chevron; collapsed controls retain accessible module names and tooltips. The sidebar stays separate from the scrolling content.

Project-wide scope pills show **Project-wide**, or **ALL** at narrow widths. Hover or focus exposes the full scope name. Ordinary Stream scopes retain their own names and stable colours. Tables can scroll horizontally when their content needs more width.

Dismissing a changed creation panel asks whether to **Discard** the draft or **Stay**. Stay preserves the draft. Discard closes the panel without creating its record. Navigation resets module search, filters and Show Deleted.

# Overview and Project Details

Overview summarises active Streams, People, Tasks, upcoming Milestones, open/high Risks, warnings and the scheduled timeline. Quick actions navigate to the relevant record module. The getting-started checklist is derived from project contents.

Choose **Edit Project** to edit Project Details. Required fields are marked; errors appear with the relevant input. Done validates and commits the draft together. Cancel or closing the dialog discards draft changes. **Show progress information** controls progress presentation without deleting stored values. Manual Project progress is a bounded percentage when displayed.

# Human-readable text and editing

On blur, human-readable names, titles, descriptions, roles, notes and action descriptions capitalise the first letter only. Subsequent case, accents and punctuation are preserved. Notes retain their meaningful whitespace; name/title trimming follows the existing record rules. Search queries, IDs, dates, numbers, filenames, URLs and other technical values are not passed through this formatting control.

A committed text edit, including its normalisation, is one Undo operation and one audit change for that edited field. Refocusing and blurring an unchanged value does not create another change. Draft forms show normalised text locally on blur but create no record/audit mutation until submitted. Cancel remains available. Unrelated edits do not reformat untouched lowercase text in a legacy project.

# Search and Filter

Search, Streams, People, Tasks, Milestones, Risk Log, Decision Log, Warnings, Gantt and Tube Map share a compact live search input within the title toolbar. Type directly to search. The filter icon at its right edge opens the page-specific filter panel. Changes apply immediately; there is no Apply button. The title stays left and record Add actions stay right. Equal outer tracks keep the 340px search field centred against the page content, independently of title/action widths. At narrower widths search uses a centred second row; controls wrap without overlap.

Search ignores case and accents, uses contains matching and requires all typed terms to match the same record. Terms can appear in any order. Module/global search includes descriptive fields beyond visible columns: notes, owners and relationship names/human IDs, dependencies and risk actions where relevant. Deleted related records are not indexed as active related names.

Multiple selections in one category are OR alternatives. Different categories combine with AND, and the query further narrows the results. Available record categories include Status, Owner and Scope; Risk Level contains Low, Medium and High even when a level currently has no records. Global Search can filter entity types and Include Deleted. Warnings can filter warning and entity types. Risk Matrix cells set the same Level filter shown in the popover.

The filter icon has a subtle active highlight while filters are selected; closing the panel preserves them. **Clear all** resets the page query and filters. Escape closes and returns focus to the trigger, including from a nested predictive filter search. Clicking outside dismisses the popover. A new module starts with fresh transient filters.

# Creation panels

Add Person, Add Stream, Add Task, Add Milestone, Add Risk and Add Decision open one consistent right-side panel with the page dimmed behind it. The existing page search remains centred and disabled while the panel is open. No alternate inline record creation row is used.

| Module | Mandatory fields | Optional creation fields |
|---|---|---|
| People | Person name | Role, Notes |
| Streams | Stream name | Description, Owner, Status, Priority, Start/End dates |
| Tasks | Task name | Description, Scope, Owner, Status, Priority, Progress, Start/End dates, Parent task, Milestone, predecessor Tasks |
| Milestones | Name, Date | Description, Status, Owner, Priority, Project-wide/multiple Streams, related Tasks, Task/Milestone predecessors |
| Risk Log | Risk title | Description, Owner, Status, probability/impact, Due date, Project-wide/Stream/Task/Milestone context, initial Risk actions with status/due dates |
| Decision Log | Title, Decision date | Additional information, Owner, Project-wide/Stream/Milestone context, related Tasks/Risks |

Defaults and model rules are retained. Task scope starts Project-wide, status Not Started and progress zero. A selected parent starts the child's scope from that parent. Milestones start Project-wide/Tentative. Risks start Open/Low/Low. Completion dates, IDs, Risk Level and rollups remain derived rather than manual creation fields.

The first mandatory text field receives focus. Tab/Shift+Tab move through visible controls; Enter from an ordinary single-line input submits for validation, and Enter in a textarea inserts a newline. Predictive search retains its selection keys. Create stays available to report missing/invalid values in reserved error slots without moving fields, focusing the first invalid mandatory field. No invalid record is created.

Successful creation closes and clears the panel, resets page search/filters/Show Deleted, refreshes data and restores Add focus. The complete record and its relationships/dependencies are one Undo/Redo operation. Cancel discards immediately. Outside-click, the close icon or Escape closes a clean panel; a changed draft uses **Discard unsaved changes?**, with Stay/Discard. Reopening starts a fresh draft. Optional fields remain editable afterwards through existing row/context controls.

# Predictive lists and relationships

Open an owner, scope, context or dependency disclosure. Type names or human-readable IDs such as PERSON-001, STREAM-003 or TASK-004. Arrow keys focus enabled matching options; Enter selects or toggles. Tab retains normal keyboard navigation. Escape closes and restores disclosure focus. Outside clicks dismiss supported disclosures; closing clears the search query.

Selection state is independent of query results. Multi-select choices remain selected when filtering hides them. Enter in a predictive search does not submit a surrounding form. Enter on an already selected single value closes without adding another edit. Short fixed entity controls, such as status, keep native select behaviour.

# People and Streams

People are lightweight ownership resources. Edit names, optional Role and Notes in the table. Delete is soft deletion; use Show Deleted and Restore where offered. Existing owner assignments use stable internal IDs, so renaming a Person does not break relationships.

Streams structure the project and provide scopes for Tasks/Milestones. Edit Stream name, Owner and Status. Displayed Stream progress derives from Tasks when progress information is enabled. Stream deletion can prompt about linked Decisions; review the confirmation. IDs are project-local and are not reused for new records merely because an older record was deleted.

# Tasks

Tasks can be Project-wide or scoped to a Stream. Change scope through the row's predictive scope selector after creation. Set optional Owner, dates, Status and leaf progress through their row controls. Task hierarchy supports up to four levels in the underlying project; parent progress derives from child work and is not edited like leaf progress.

The Dependencies disclosure edits predecessor Tasks. Circular dependencies are prevented; an unavailable option may be disabled. Finish-to-Start relationships can produce warnings when dates conflict; they do not automatically reschedule work. Optional predecessors can be selected in the creation panel or edited afterwards.

Rows expose duplicate, soft-delete and restore actions as applicable. Select multiple Tasks for bulk deletion and review its confirmation. Dependency/relationship cleanup follows the existing command rules. Undo/Redo is global across modules.

# Milestones

A Milestone has a required date and one canonical identity. It can be Project-wide or associated with several Streams. Its scope selector supports predictive Stream matching; a shared Milestone may appear in multiple chart lanes without becoming duplicate records.

Edit date, Status, Owner, scope and predecessors through the table. Predecessors may be Tasks or other Milestones where supported. Circular relationships are prevented and dependency warnings can be expanded. Completing/reopening follows the existing completion-date rules. Duplication creates a new identity; deletion is soft and may require confirmation for linked/dependent records.

# Gantt

Gantt projects the canonical Project-wide/Stream/Task/Milestone data. It does not own a separate project. Use Week, Month or Quarter zoom. Previous/Next and Jump to today are in the persistent footer below the chart, alongside its inclusive DD/MM/YYYY visible date range. Each navigation step retains the existing increment: one day at Week zoom, seven days at Month, fourteen days at Quarter. Jump to today preserves the enabled Gantt Today action; changing zoom resets the window. Tube Map retains its disabled-at-origin Jump to today state. The toolbar retains Expand All, Collapse All and Zoom. Expand/collapse each section or use Expand All / Collapse All. The Stream heading supports sorting; a Stream name opens its record module.

Task labels open a compact name/start/end quick editor. Save commits changes through the normal command history; Cancel discards the quick-editor draft. Open Task navigates to Tasks. Milestone labels navigate to Milestones. Both dates are needed for a scheduled Task bar; missing dates are indicated as unscheduled, and out-of-window records remain in the project.

The padded hierarchy labels and shared dotted red Today marker start below date headers. The marker spans the timeline body. Visible Finish-to-Start connectors derive from the currently displayed rows. The chart scrolls independently above its footer, keeping navigation accessible without covering dependency information or the last row.

Gantt has one Hide Empty Streams checkbox inside its filter panel; it is not duplicated in the chart toolbar. A Stream is populated by any non-deleted Task or assigned Milestone, including undated/out-of-window work and parents with deleted children. Each associated Stream counts for a shared Milestone. Deleted records do not populate a Stream.

# Tube Map

Tube Map shows Streams as lanes and Milestones as stations; it deliberately does not show Tasks. The Axis control switches Week Number/Monday date labels. Previous/Next move the window by four weeks; Jump to today returns to the current window. Boundary counts indicate Milestones before/after the visible window.

A station diamond or label opens a Milestone quick editor with name/date. Save commits; Cancel discards; Open Milestone navigates to its record. Shared scope is represented from the same canonical Milestone. The shared red dotted Today marker spans the chart body beneath date headers.

Tube Map has its own independent Hide Empty Streams checkbox inside its filter panel; it is not duplicated in the chart toolbar. Only non-deleted Milestones populate its lanes; Tasks alone do not. Undated/out-of-window and multi-stream membership follow the approved counting rules. This setting is not a shared switch with Gantt.

# Risk Log

Use probability and impact controls to maintain Low/Medium/High ratings and the derived Risk Level. The matrix shows matching record counts; selecting a cell sets the shared Level filter. Status is a separate editable fixed list.

**Edit context** opens a draft for Owner, Project-wide flag, Stream/Task/Milestone links and Description. Predictive lists search names/human IDs and preserve hidden selections. Save context commits; Cancel discards. Ctrl/Cmd+Enter submits multiline context.

**Actions** expands action descriptions, status and due dates. Action descriptions normalise as one text edit on blur. Open overdue actions contribute warnings as defined by the project model. Duplicate/delete/restore actions follow the existing local record history.

# Decision Log

Create a title/date record, then edit its Owner and context. **Edit context** exposes Project-wide scope, Stream/Milestone links, Task/Risk links and Additional information. Project-wide is exclusive with the Stream/Milestone scope choices; independent Task/Risk context remains available. The redundant Context display column is hidden; underlying relationships are retained.

Context edits are drafts. Save commits together; Cancel discards; Ctrl/Cmd+Enter saves multiline notes. Unchanged values do not add history. Duplication creates a fresh identity/current date according to existing rules. Soft deletion and restore remain available.

# Warnings and global Search

Warnings are derived from current data, not persisted as a separate record collection. They disappear when corrected. Filter by warning/entity types and live text. Open navigates to the affected entity. Supported correction actions use ordinary project commands and can be undone; warnings that need a replacement scope direct you to Milestones rather than removing its final valid scope silently.

Global Search groups results by entity and offers Open details. Include Deleted allows discovery of soft-deleted records; supported results offer Restore. Returning to a record uses stable IDs and may highlight the target. Search state itself is transient and is not written to the project file.

# Audit Log (experimental)

File Information contains **Enable change history**, off by default. When enabled, successful project changes append field-oriented events to this `.pmp` project. The latest 5,000 are retained. Disabling recording preserves existing events.

Show audit data exposes up to 50 matching rows. Filter the retained history, toggle Newest first / Oldest first, or Export CSV for the full history regardless of the current filter. Exports escape spreadsheet formula injection. Undo/Redo changes are recorded when audit recording is enabled. There is no separate formatting event for the same normalised text edit.

Audit history is experimental and is not an external compliance or immutable event service. Its optional payload remains within the local project file.

# Keyboard reference

| Key | Context and behaviour |
|---|---|
| Tab / Shift+Tab | Move between controls; dialogs retain focus within their controls |
| Enter | Submit a single-line creation form or choose the focused predictive result |
| Arrow Up / Down | Navigate predictive matching results |
| Escape | Close a predictive disclosure/popover; dialogs cancel/close as labelled |
| Ctrl/Cmd+Enter | Submit supported multiline context drafts |
| Ctrl/Cmd+S | Save the active project |
| Ctrl/Cmd+Z | Undo the last committed project edit |
| Ctrl/Cmd+Y or Ctrl/Cmd+Shift+Z | Redo |
| Ctrl/Cmd+K | Navigate to global Search |

Search/filter typing is not subject to human-readable text capitalisation. Permission/picker dialogs use the platform's keyboard conventions.

# Compatibility, backups and acceptance

v1.4 `.pmp` projects use the existing supported format/schema and open without a silent schema migration. Untouched values, stable identities, relationships, deleted records, configuration and optional audit history are retained. A successful v1.5 save can add optional saving-device timezone metadata and records the candidate runtime version. Older technical schemas still follow the documented explicit migration boundary; unsupported future containers are rejected.

Back up real files before acceptance. Test open, edit, save, close, reopen and Save As, then compare all entity fields/relationships and file history. Browser regression uses an in-memory file-picker adapter and cannot certify real Windows/macOS permission behaviour. Use `V1.5_DESKTOP_ACCEPTANCE.md` and `V1.5_COMPATIBILITY.md` for native tests and the readiness register for unresolved gates.

A candidate is not approved for merge, tagging, deployment or publication merely because automated checks pass. The final pushed SHA must have verified CI evidence, manual desktop/native results and explicit release approval.
