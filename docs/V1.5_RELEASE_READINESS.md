## Consolidated verification procedure

1. Complete and review each row above, attaching a test, screenshot or review note; **do not mark a row passed from a green CI run alone**.
2. Run one final automated cycle on the exact intended release candidate commit: `npm ci`, `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`, `npm audit --omit=dev --audit-level=moderate`, `npm run test:regression`, and `npm run test:lifecycle`.
3. Check the repository's validation and lifecycle workflow conclusions for that same commit, plus any security audit result.
4. Confirm v1.5 UI manual and demo assets, release notes, and migration/compatibility documentation. Review Dependabot target branch and remove any temporary release-only workflows before merge.
5. Record any unresolved gaps explicitly and obtain user acceptance for desktop visual checks. Only then request approval to merge and release.

## Release-candidate control

- **Freeze the candidate commit** before the consolidated verification run. Do not add cosmetic changes after the freeze; any corrective commit starts a new candidate and requires revalidation.
- **Review the full diff against `main`**, including changes to dependencies, persistence, CI, documentation and demo assets. The branch is substantially ahead of `main`; green tests alone do not establish scope completeness.
- **Separate automated evidence from visual acceptance.** GitHub Actions can verify functionality and regression suites, but cannot approve the desktop UI on behalf of the user.
- **Keep a single outstanding-gaps register** for missing requirements, failed tests and manual findings. Record severity, reproduction, proposed correction and retest outcome.
- **Present a single release decision** only when every mandatory acceptance row has evidence and the candidate commit has passed all required checks.
